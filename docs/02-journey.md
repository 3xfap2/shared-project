# 2. Цель проекта, ценностное предложение и пользовательские пути

## 2.1. Цель проекта

**Стратегическая цель.**
Превратить «Чистый берег» из серии разовых уборок в постоянно действующую
образовательную систему наблюдения за береговыми территориями, где обучение
работе с данными ДЗЗ является одновременно и продуктом просвещения, и
инструментом реальной природоохранной работы.

**Цель на горизонт пилота (12 месяцев).**

| Что | Целевое значение | Комментарий |
|---|---|---|
| Регион пилота | 1 регион, 2–3 ООПТ | Допущение D1 |
| Зарегистрированные пользователи | 3 000 | См. расчёт воронки в разделе 7 |
| Завершившие обучение | 750 | Ключевой образовательный результат |
| Вышедшие на офлайн-акцию | 225 | Переход «онлайн → поле» |
| Повторно участвующие | 80 | Ядро устойчивого сообщества |
| Участков под наблюдением | 150+ | Рабочий актив для ООПТ |

**Ключевая продуктовая идея в одном предложении.**

> КОСМОБЕРЕГ учит человека читать снимок своего берега, приводит его на этот
> берег и возвращает результат его работы в систему как проверенные данные,
> которыми пользуется ООПТ.

## 2.2. Сквозная логика системы — «замкнутый цикл»

Это ядро концепции: каждое звено даёт вход следующему, а последнее возвращает
данные в первое. Ни одна аудитория не является «придатком» — обе необходимы для
работы цикла.

```
        ┌──────────────────────────────────────────────────────────┐
        │                                                          │
        v                                                          │
┌───────────────┐    ┌───────────────┐    ┌───────────────┐    ┌───────────────┐
│  1. СПУТНИК   │    │  2. ОБУЧЕНИЕ  │    │  3. ПОЛЕ      │    │  4. ЭФФЕКТ    │
│               │───▶│               │───▶│               │───▶│               │
│ Снимки ДЗЗ    │    │ Волонтёр      │    │ Экспедиция:   │    │ Фото «до/     │
│ дают «зоны    │    │ учится читать │    │ уборка +      │    │ после» +      │
│ внимания» на  │    │ снимок и      │    │ наземная      │    │ проверка ООПТ │
│ береговой     │    │ размечает     │    │ фиксация      │    │ = достоверная │
│ линии         │    │ реальные тайлы│    │ состояния     │    │ точка данных  │
└───────────────┘    └───────────────┘    └───────────────┘    └───────────────┘
        ▲                    │                                          │
        │                    │  разметка = обучающая практика           │
        │                    ▼  и одновременно полезный сигнал          │
        │            ┌───────────────────┐                              │
        └────────────│  5. КАБИНЕТ ООПТ  │◀─────────────────────────────┘
    уточнённые       │ Приоритеты, план  │
    приоритеты       │ обходов, акции,   │
                     │ отчётность        │
                     └───────────────────┘
```

**Почему цикл замкнут и это важно для защиты:**
- Спутник даёт **гипотезу** («здесь что-то изменилось»).
- Волонтёр в обучении даёт **разметку** (дешёвую, массовую, но требующую проверки).
- Выход в поле даёт **истину на земле** (ground truth) — фото с геометкой.
- ООПТ даёт **валидацию** (экспертное подтверждение).
- Проверенные данные **уточняют приоритеты** следующего цикла.

Обучение здесь — не отдельный раздел «для галочки», а рабочий узел цикла.
Это прямой ответ на критерий «обучение и тематика ДЗЗ встроены в
пользовательский путь, механики или цифровой продукт».

## 2.3. Пользовательский путь: молодёжь 14+

| Этап | Что происходит | Барьер этапа | Механика перевода на следующий этап | Роль цифрового продукта |
|---|---|---|---|---|
| **0. Первый контакт** | Видит проект: урок в школе, ролик, соцсети, партнёрская активность вуза | «Ещё одна скучная экология» | Крючок «**Твой берег из космоса**»: показываем снимок знакомого места | Лендинг с картой: вводит свой город → видит реальный снимок берега рядом |
| **1. Интерес → первое действие (3 мин)** | Пробует мини-игру: сравнить снимки «до/после» и отметить изменение | «Долго, сложно, надо регистрироваться» | **Действие до регистрации.** Первый разбор — без аккаунта | Мини-тренажёр разметки, работает сразу, результат сразу |
| **2. Знакомство и регистрация** | Получает результат мини-игры и видит, чего не хватает | Нежелание оставлять данные | Результат «заперт»: «Сохрани прогресс и получи доступ к реальным участкам» | Быстрая регистрация; для 14–17 — флоу согласия родителя |
| **3. Обучение** | Проходит курс «**Школа наблюдателя Земли**»: 3 модуля по 5–7 минут | Отсев на середине курса | Микроформат + практика на реальных тайлах после каждого модуля + прогресс-бар | LMS-модуль: теория → практика → автопроверка → бейдж |
| **4. Завершение обучения** | Получает статус «Наблюдатель» и допуск к реальной разметке | «И что дальше?» | Статус открывает доступ: разметка попадает в рабочую очередь ООПТ | Сертификат в профиле; разблокировка функции реальной разметки |
| **5. Первое полевое участие** | Записывается на экспедицию на участок, который **сам размечал** | Логистика, страх первого раза, согласие родителей | **Персональная привязка:** «Ты отметил этот участок — поедешь его убирать». Командная запись «приведи друга» | Календарь акций, запись, чек-лист снаряжения, цифровой инструктаж, электронное согласие |
| **6. Подтверждение эффекта** | Загружает фото «до/после» с геометкой; ООПТ подтверждает | «Эффекта всё равно нет» | **Слайдер «до/после»** и отметка на карте: участок меняет статус на «чистый» | Загрузка гео-фото, статус модерации, обновление карты |
| **7. Признание и польза** | Получает часы волонтёрства, сертификат, место в рейтинге | — | Учёт часов через ДОБРО.РФ, командный рейтинг школ/вузов | Профиль, выгрузка для портфолио, рейтинги |
| **8. Повторное участие** | Возвращается: наблюдает «свой» участок, зовёт команду | Угасание интереса | **Подписка на участок:** уведомление при новом снимке. Сезонные челленджи. Рост роли | Подписки, пуш-уведомления, трек развития до «Амбассадора» |
| **9. Ядро сообщества** | Становится амбассадором: сам организует выходы, обучает новичков | — | Программа амбассадоров, доступ к расширенной аналитике | Роль «Амбассадор» с правом создавать заявки на акции |

**Ключевая находка пути:** самый узкий переход — **этап 4 → 5 (онлайн → поле)**.
Мы закрываем его не призывом, а **персональной привязкой**: волонтёр едет
убирать именно тот участок, который сам нашёл на снимке. Это единственная
механика, которую невозможно скопировать без ДЗЗ-слоя.

## 2.4. Пользовательский путь: сотрудники ООПТ

| Этап | Что происходит | Барьер этапа | Механика перевода | Роль цифрового продукта |
|---|---|---|---|---|
| **0. Первый контакт** | Узнаёт через профильное сообщество, вебинар, письмо, партнёрство с Минприроды | «Очередная система, которую надо вести» | Заход через **боль**, а не через технологию: «сколько км берега вы не обходите?» | — (офлайн/почта) |
| **1. Демонстрация на своей территории** | Видит демо **на снимке своей ООПТ** с реальными зонами внимания | Недоверие: «у вас там общие картинки» | **Демо на собственных данных** — сильнейший аргумент | Генерация демо-карты по кадастровым границам ООПТ |
| **2. Подключение территории** | Заводит территорию, задаёт участки береговой линии | «Нет времени на настройку» | Настройку выполняет команда проекта, сотрудник только подтверждает | Мастер подключения; импорт границ (GeoJSON/shape) |
| **3. Освоение инструмента** | Короткое обучение (45 мин) работе с кабинетом | Низкие цифровые навыки | Один рабочий экран; методичка; сопровождение куратора | Кабинет ООПТ: карта приоритетов + очередь модерации |
| **4. Первая акция** | Создаёт акцию на приоритетном участке, получает волонтёров | Ответственность за людей на территории | Готовый пакет: шаблон акции, инструктаж, согласия, ТБ | Конструктор акции, авто-инструктаж, электронные согласия |
| **5. Получение ценности** | Получает проверенные отчёты и обновлённую карту | Поток шума от волонтёров | **Контур верификации:** консенсус 3 разметок → в очередь; сотрудник только подтверждает/отклоняет | Модерация в 2 клика; фильтр по уверенности |
| **6. Регулярное использование** | Планирует обходы по карте приоритетов | «Не встраивается в отчётность» | Выгрузка в готовом виде для внутренних отчётов | Экспорт PDF/CSV/GeoJSON, история по участку |
| **7. Расширение** | Рекомендует систему коллегам, подключает новые участки | — | Сообщество ООПТ-пользователей, обмен практиками | Мультитерриториальный режим |

**Ключевая находка пути:** барьер ООПТ — не технологический, а **доверие и
нагрузка**. Поэтому продукт спроектирован так, чтобы сотрудник ООПТ **никогда
не делал работу, которую может сделать волонтёр или система**: он только
подтверждает или отклоняет готовое решение.

## 2.5. Точка встречи двух путей

Аудитории не живут в продукте параллельно — они соединены в трёх точках:

| Точка встречи | Молодёжь даёт | ООПТ даёт | Результат |
|---|---|---|---|
| **Разметка** | Массовую дешёвую разметку снимков | Экспертное подтверждение | Достоверный слой «зон внимания» |
| **Акция** | Рабочие руки и наземную фиксацию | Легитимность, доступ, инструктаж, ТБ | Легальная уборка на охраняемой территории |
| **Верификация** | Фото «до/после» с геометкой | Финальное подтверждение статуса | Данные, пригодные для отчётности |

Именно поэтому продукт **обязателен** и не заменяется серией мероприятий:
без цифрового контура нет ни разметки, ни верификации, ни приоритизации —
цикл рвётся.
