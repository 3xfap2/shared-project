# Контракт API — правила совместной работы

Этот каталог — **граница между фронтендом и бэкендом**. Две команды (и два
ассистента) работают параллельно, не блокируя друг друга, потому что обе
кодируют против одного контракта.

## Главное правило

> **Сначала правим `openapi.yaml`, потом код.**

Любое изменение интерфейса — новое поле, переименование, новый эндпоинт —
сначала попадает в контракт и согласуется. Код, разошедшийся с контрактом,
считается сломанным, даже если он работает.

## Разделение зон

| Зона | Кто ведёт | Файлы |
|---|---|---|
| **Контракт** | Совместно, по согласованию | `contract/openapi.yaml` |
| **Фронтенд** | Команда фронта | `frontend/**`, `prototype/**` |
| **Бэкенд** | Команда бэка | `backend/**` |
| **Документы паспорта** | Совместно | `docs/**` |
| **Презентация** | Совместно | `presentation/**` |

Правки в чужую зону — только через договорённость. Это единственный способ
избежать конфликтов при слиянии.

## Как работать, пока бэка нет

Фронт не ждёт бэкенд. Порядок такой:

1. Контракт описывает эндпоинт.
2. Фронт делает мок-слой, отдающий ответы по схемам из контракта.
3. Бэк реализует те же схемы.
4. Стыковка = смена базового URL с мока на `http://localhost:8000/api/v1`.

Сгенерировать типы и клиент из контракта:

```bash
# TypeScript-типы для фронта
npx openapi-typescript contract/openapi.yaml -o frontend/src/api/schema.ts

# Проверка контракта на валидность
npx @redocly/cli lint contract/openapi.yaml

# Читаемая документация в браузере
npx @redocly/cli preview-docs contract/openapi.yaml
```

## Два решения, которые нельзя нарушать

### 1. Локализация — на клиенте, не на сервере

API **не возвращает переведённый текст**. Только доменные коды и ключи словаря:

```jsonc
// Так — правильно
{ "status": "problem", "name_key": "seg.ustie.name", "attention_index": 77 }

// Так — нельзя
{ "status": "Проблемный", "name": "Устье реки Каменки" }
```

Перевод выполняет `prototype/i18n.js` (ru / en / zh). Благодаря этому смена
языка не требует запроса к серверу, а четвёртый язык не затрагивает бэкенд.

Исключение — пользовательский контент (имена, комментарии в отчётах):
возвращается как есть.

Ошибки тоже приходят ключом:

```jsonc
{ "code": "consent_required", "message_key": "err.consent_required" }
```

### 2. Критичная логика — только на сервере

Клиенту нельзя доверять расчёт того, что даёт права или влияет на данные ООПТ.
Сервер вычисляет и никогда не принимает от фронта:

- `attention_index` и факторы `s`, `c`, `t`, `a`;
- переход роли `student → observer` (только после реального завершения курса);
- достижение консенсуса по разметке;
- допуск на акцию (курс + согласие родителя для 14–17);
- смену статуса участка.

Фронт эти значения **отображает**, а не вычисляет. В прототипе логика считается
на клиенте только потому, что бэка ещё нет — при переезде она уходит на сервер
без изменения интерфейса.

## Соответствие сценариям паспорта

Контракт покрывает сквозной сценарий S1 → S6 из
[паспорта, раздел 5.5](../docs/04-product.md):

| Сценарий | Эндпоинты |
|---|---|
| **S1** Первый контакт | `GET /public/trainer/task`, `GET /public/stats`, `POST /auth/register` |
| **S2** Обучение | `GET /course/modules`, `POST /course/modules/{id}/answer` |
| **S3** Разметка | `GET /annotations/task`, `POST /annotations` |
| **S4** Кабинет ООПТ | `GET /moderation/segments`, `POST /moderation/segments/{id}`, `POST /events` |
| **S5** Акция | `POST /events/{id}/enrollment`, `.../consent`, `.../briefing` |
| **S6** Полевой отчёт | `POST /media/upload`, `POST /reports`, `PATCH /reports/{id}`, `POST /moderation/reports/{id}` |

Если во фронте появляется экран, которому нужны данные, не описанные в
контракте, — это сигнал, что контракт неполон. Не придумывайте формат на месте,
допишите его сюда.

## Порядок реализации бэкенда

Приоритет — по тому, что раньше нужно фронту:

1. `auth` + `course` — без них не пройти S1–S2
2. `segments` — основа карты и кабинета ООПТ
3. `annotations` + `moderation/segments` — S3–S4
4. `events` + `enrollment` — S5, включая проверку допуска
5. `media` + `reports` + `moderation/reports` — S6, замыкание цикла
6. `export` — последним, нужен только для отчётности
