# КОСМОБЕРЕГ

**Цифровая платформа развития образовательного проекта «Чистый берег»**

Решение кейса Космохакатона: популяризация образовательного проекта «Чистый берег»
через связку данных дистанционного зондирования Земли и волонтёрского участия.

---

## Идея в одном абзаце

Между космическими данными и людьми на берегу нет двустороннего канала.
Молодёжи не хватает смысла и данных, ООПТ — рук и глаз, а снимки ДЗЗ не доходят
ни до тех, ни до других. **КОСМОБЕРЕГ учит человека читать снимок своего берега,
приводит его на этот берег и возвращает результат его работы в систему как
проверенные данные, которыми пользуется ООПТ.**

```
┌─ 1. СПУТНИК ──┐   ┌─ 2. ОБУЧЕНИЕ ─┐   ┌─ 3. ПОЛЕ ────┐   ┌─ 4. ЭФФЕКТ ──┐
│ Снимки ДЗЗ    │──▶│ Волонтёр учит-│──▶│ Экспедиция:  │──▶│ Фото до/после│
│ дают «зоны    │   │ ся читать сни-│   │ уборка +     │   │ + проверка   │
│ внимания»     │   │ мок, размечает│   │ фиксация     │   │ ООПТ         │
└───────────────┘   └───────────────┘   └──────────────┘   └──────────────┘
        ▲                                                          │
        └──────── 5. КАБИНЕТ ООПТ: приоритеты, акции, отчёты ◀─────┘
```

Цикл замкнут: обучение волонтёра — не предисловие к уборке, а **рабочий узел
системы**, дающий разметку, которая после верификации уточняет приоритеты.

## Быстрый старт прототипа

### Вариант 1 — без установки (самый быстрый)

Открыть файл `prototype/index.html` в любом современном браузере.
Внешние зависимости отсутствуют, сборка не требуется.

### Вариант 2 — Docker: вся система целиком

```bash
docker compose up --build
```

Поднимает PostGIS, применяет миграции, заполняет демо-данными и запускает всё:

| Что | Адрес |
|---|---|
| Прототип | http://localhost:8080 |
| API бэкенда | http://localhost:8000 |
| Интерактивная документация API | http://localhost:8000/docs |

### Вариант 3 — проверка сквозного сценария без браузера

```bash
node prototype/e2e-check.js
```

Скрипт прогоняет состояние по всем шагам S1→S6 на заглушке DOM и проверяет
29 утверждений **на каждом из трёх языков**, включая **замыкание цикла**:
после подтверждённой уборки индекс внимания участка падает с **85 до 48**
и приоритет переходит на следующий участок.

Те же числа проверяет `backend/tests/test_cross_check.py`, прогоняя настоящий
консенсус через API. Если формула разойдётся на любой из сторон, оба набора
тестов упадут.

## Мультиязычность

Интерфейс переключается между тремя языками кнопками в верхней панели:

| Язык | Код | Назначение |
|---|---|---|
| Русский | `ru` | Основной язык проекта и защиты |
| English | `en` | Международные эксперты, публикация методики |
| 中文 | `zh` | Международное партнёрство и тиражирование модели |

Реализация — словарь `prototype/i18n.js`: **235 ключей × 3 языка**, с проверкой
согласованности ключей и плейсхолдеров. Переводится весь интерфейс, включая
названия участков, статусы, учебный курс и **журнал системы** — он хранит ключ
и параметры, а не готовую строку, поэтому при смене языка перерисовывается
целиком. Выбор языка сохраняется в `localStorage`.

Добавление четвёртого языка = один новый объект в `i18n.js`, изменений в коде
приложения не требуется.

## Как пройти прототип за 3 минуты

Кнопки сценариев в верхней панели открываются по мере прохождения — это
намеренно: продукт не даёт разметить реальные данные до завершения обучения.

| Шаг | Что сделать | Что проверяется |
|---|---|---|
| **S1** | Ввести город → кликнуть на снимке «после» там, где появилось изменение | Ценность до регистрации; первое действие занимает 30 секунд |
| — | Зарегистрироваться, **выбрав возраст 14–17** | Возрастной режим работы с ПДн |
| **S2** | Пройти 3 модуля курса с практикой | Обучение конвертируется в допуск, роль → «Наблюдатель» |
| **S3** | Отметить зону на реальном снимке, выбрать вердикт | Разметка достигает консенсуса 3/3 и уходит в очередь ООПТ |
| **S4** | Подтвердить участок → создать акцию | Модерация в 2 клика; участок возглавляет карту приоритетов |
| **S5** | Записаться → отправить согласие родителя → пройти инструктаж | Жёсткая проверка допуска несовершеннолетнего |
| **S6** | Зафиксировать «до» → отправить отчёт → подтвердить его в S4 | Статус → «Чистый», пересчёт индекса, цикл замкнулся |

Кнопка **«Сбросить»** возвращает прототип в исходное состояние.

> **Что в прототипе демонстрационное:** снимки ДЗЗ и наземные фото генерируются
> процедурно (без внешних зависимостей и сетевых запросов). В боевой системе на
> их месте — тайлы COG из конвейера обработки ДЗЗ, см.
> [архитектуру, раздел 6.3](docs/05-architecture.md).
> **Что настоящее:** вся продуктовая логика — расчёт индекса внимания, консенсус
> разметки, репутация, ролевая модель, проверка допуска, пересчёт приоритетов
> после уборки.

## Ключевые решения и их обоснование

1. **ML-детекция мусора на MVP не строится.** Критерий прямо допускает, что
   техническая обработка данных ДЗЗ не обязательна. Спутник даёт грубый сигнал
   изменения, точность обеспечивают консенсус волонтёров и проверка ООПТ.
   Побочный эффект — накапливается размеченный датасет для модели на этапе 2.
   Экономия ~1.5 млн ₽.

2. **Вес спутникового сигнала ограничен 0.40.** Формула индекса внимания открыта
   и объяснима: сотрудник ООПТ должен понимать, почему участок наверху списка,
   иначе не будет доверия. Спутник не может в одиночку поднять участок наверх.

3. **Разметка Ученика не попадает в рабочую очередь.** Ролевая модель — прямой
   ответ на барьер недоверия ООПТ к волонтёрским данным.

4. **PWA вместо нативных приложений.** Закрывает камеру, геолокацию и офлайн-режим,
   экономит ~2 млн ₽ и месяцы разработки.

5. **Источник данных ДЗЗ абстрагирован.** Если доступ к российской орбитальной
   группировке не будет получен на приемлемых условиях, система работает на
   Sentinel-2 и аэросъёмке БПЛА без изменения архитектуры.

6. **Связь с ДЗЗ двусторонняя.** Инспектор не только получает снимки, но и
   заказывает съёмку конкретного участка через оператора — Геопортал Роскосмоса
   принимает такие заявки штатно. Мониторинг перестаёт зависеть от случайного
   пролёта спутника.

7. **Доверие к волонтёрам измеряется, а не декларируется.** Скрытые эталонные
   задания дают инспектору точность каждого разметчика в цифрах. Приём
   заимствован у Zooniverse, где на миллиарде разметок доказал, что
   неспециалисты дают пригодные данные при правильной проверке.

8. **Контур не привязан к мусору.** Ни один компонент логики не знает
   предметной области: слово «свалка» живёт в перечислении вердиктов и в
   курсе, то есть в данных. Перенос на мониторинг последствий пожаров или
   подтоплений — новый обучающий трек, а не переписывание системы. Масштаб
   задачи и условия такого шага — [паспорт, раздел 10.5](docs/06-kpi-plan.md).

9. **Срочность важнее размера.** Детектор роста поднимает в приоритете
   растущую аномалию независимо от её абсолютной площади. Основано на
   подтверждённом кейсе: по данным «Ресурс-П» фиксировался именно рост свалки
   у заповедника за 2017–2019 годы.

## Ограничения, которые мы признаём честно

- Экологический эффект за 12 месяцев пилота **не доказывается** — показывается
  причинно-следственная цепочка, каждое звено которой измеримо, и вводится
  контрольная ООПТ без цифрового контура.
- Самое узкое место модели — переход **«онлайн → поле»** (30% обученных).
  Это главный продуктовый риск R-P2, и метрика P1 — основной индикатор пилота.
- Все количественные ориентиры воронки и сметы — **обоснованные допущения**,
  зафиксированные в [реестре](docs/00-assumptions.md), а не измеренные факты.
