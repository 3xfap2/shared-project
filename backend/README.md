# Бэкенд КОСМОБЕРЕГ

FastAPI + PostgreSQL/PostGIS. Реализует [`contract/openapi.yaml`](../contract/openapi.yaml)
— 35 операций, сверка контракта и кода автоматическая (см. ниже).

## Запуск

### Docker — всё вместе, одной командой

```bash
docker compose up --build          # из корня репозитория
```

Поднимает PostGIS, применяет миграции, заполняет демо-данными и запускает API.

- API — http://localhost:8000
- Интерактивная документация — http://localhost:8000/docs
- Прототип — http://localhost:8080

### Локально, без Docker

На SQLite — база файлом, ничего ставить не нужно:

```bash
python -m venv .venv && .venv/Scripts/activate    # Windows
pip install -r requirements.txt
python -m app.db.seed                              # демо-данные
uvicorn app.main:app --reload
```

Демо-доступы после сидов:

| Роль | Логин | Пароль |
|---|---|---|
| Сотрудник ООПТ | `inspector@kosmobereg.ru` | `Inspector-123` |
| Администратор | `admin@kosmobereg.ru` | `Admin-123` |

Волонтёра заводите через `POST /api/v1/auth/register` — так проверяется
сценарий S1 целиком.

### Проверка соответствия контракту

```bash
python - <<'PY'
import sys, yaml; sys.path.insert(0, '.')
from app.main import app
from app.core.config import settings
c = yaml.safe_load(open('../contract/openapi.yaml', encoding='utf-8'))
prefix = settings.API_V1_PREFIX
contract = {(m.upper(), p) for p, it in c['paths'].items()
            for m in it if m in ('get','post','put','patch','delete')}
backend = {(m, r.path[len(prefix):]) for r in app.routes
           if hasattr(r,'methods') and r.path.startswith(prefix)
           for m in r.methods - {'HEAD','OPTIONS'}}
print('только в контракте:', sorted(contract - backend) or 'НЕТ')
print('только на бэке:', sorted(backend - contract) or 'НЕТ')
PY
```

Обе строки должны быть «НЕТ». Эта проверка уже находила три эндпоинта,
о которых фронт не знал, и один затёртый в контракте метод.

### Доменная логика — ядро продукта

| Модуль | Отвечает за |
|---|---|
| `attention.py` | Индекс внимания `0.40·S + 0.30·C + 0.20·T + 0.10·A`. **Единственное место пересчёта** |
| `consensus.py` | Консенсус разметки, взвешенный по репутации |
| `calibration.py` | Скрытые эталонные задания — измерение реальной точности разметчиков |
| `growth.py` | Детектор растущей аномалии |
| `enrollment.py` | Допуск на акцию. Самая ответственная логика: несовершеннолетние |
| `course.py` | Курс и присвоение роли «Наблюдатель» |

## Решения, которые стоит понимать до правок

**Формула индекса неприкосновенна.** `attention_index` пересчитывается только
в `services/attention.recalculate()`. Присваивание в другом месте означает
рассинхрон факторов и индекса — инспектор поедет не туда. Детектор роста
намеренно усиливает фактор `S`, а не добавляет пятое слагаемое: паспорт,
презентация и прототип остаются верными.

**Локализация — на клиенте.** API отдаёт коды и ключи (`status: "problem"`,
`name_key: "seg.ustie.name"`, `message_key: "err.consent_required"`), а не текст.
Словарь на трёх языках уже есть во фронте; дублировать его на сервере незачем,
а четвёртый язык не должен затрагивать бэкенд.

**Критичное считает сервер.** Индекс и факторы, повышение роли до `observer`,
консенсус, допуск на акцию, смена статуса участка — всё вычисляется на сервере
и никогда не принимается от клиента.

**Возраст хранится годом рождения.** Возраст протухает: зарегистрировавшийся
в 17 через год остался бы семнадцатилетним, и система требовала бы согласие
родителя у совершеннолетнего. Известное ограничение — точность ±1 год,
ошибаемся в безопасную сторону.

**Признак контрольного задания не покидает сервер.** Схема `AnnotationTaskOut`
намеренно его не содержит. Как только волонтёр узнаёт о проверке, он работает
иначе — и измерение перестаёт отражать его обычную точность. Пользователи
предупреждены о контроле качества в условиях использования.

**Геометрия хранится как GeoJSON в JSON-колонке.** В контракте v1 нет ни одного
пространственного запроса, а JSON работает и на PostgreSQL, и на SQLite —
поэтому тесты идут без Docker. PostGIS-колонка с GiST-индексом появится
отдельной миграцией, когда придёт первый реальный геозапрос: привязка фото
по геометке к ближайшему участку.

## Миграции

```bash
alembic upgrade head                       # применить
alembic revision --autogenerate -m "..."   # создать после правки моделей
```

URL базы берётся из настроек приложения, а не из `alembic.ini`: иначе адрес
пришлось бы держать в двух местах.

## Что не сделано осознанно

| Не сделано | Почему |
|---|---|
| ML-детекция мусора | Критерий прямо допускает отсутствие; точность обеспечивают люди через консенсус. Экономия ~1.5 млн ₽ |
| Реальная интеграция с Геопорталом | Требует договора с оператором. Модель и эндпоинты готовы, статусы заявок переключаются вручную |
| Отправка писем и push | `services/notifications.py` — интерфейс с логированием, готовый под FCM и SMTP |
| Загрузка фото в S3 | На MVP файлы на диске; интерфейс совпадает с S3, меняется только реализация записи |
| Обновление `factor_s` из растров | Конвейер ДЗЗ (компонент E) — отдельный сервис; бэкенд принимает готовый сигнал |
